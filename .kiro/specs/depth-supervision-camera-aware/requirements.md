# 需求文档

## 简介

本文档定义了在BEVFusion框架中增强图像分支的两个关键特性：**LiDAR深度监督**和**Camera-Aware深度估计**。

当前BEVFusion的图像分支使用LSS（Lift-Splat-Shoot）方法将2D图像特征转换到BEV空间。现有的`DepthLSSTransform`仅利用图像特征进行隐式的深度推断，缺乏显式的几何监督，且对不同相机的内参和外参差异不敏感。

本设计旨在：
1. **LiDAR深度监督**：引入深度估计损失函数，利用LiDAR投影的稀疏深度作为监督信号，显式优化深度预测网络
2. **Camera-Aware**：使深度估计网络能够感知不同相机的内参、外参和数据增强差异，针对不同相机自适应调整深度预测

## 术语表

- **LSS (Lift-Splat-Shoot)**: 一种将2D图像特征转换到3D BEV空间的视角变换方法
- **深度监督 (Depth_Supervision)**: 使用LiDAR投影的稀疏深度作为GT，计算深度预测损失
- **Camera-Aware**: 相机感知，使网络能够根据不同相机的内参、外参和数据增强调整深度预测
- **稀疏深度图 (Sparse_Depth_Map)**: 将LiDAR点云投影到图像平面生成的深度图，只有部分像素有深度值
- **深度分布 (Depth_Distribution)**: 网络预测的每个像素在不同深度bin上的概率分布
- **深度bin (Depth_Bin)**: 将连续深度范围离散化为固定数量的区间
- **相机内参 (Camera_Intrinsics)**: 相机的焦距(fx, fy)和主点(cx, cy)等参数
- **相机外参 (Camera_Extrinsics)**: 相机相对于LiDAR的旋转和平移变换
- **IDA (Image_Data_Augmentation)**: 图像数据增强矩阵，包含缩放、裁剪、翻转等变换
- **SE模块 (Squeeze_and_Excitation)**: 一种通道注意力机制，用于特征调制
- **Focal Loss**: 一种处理类别不平衡的损失函数，对难分类样本给予更高权重
- **Min Pooling**: 最小深度池化，当多个点落入同一网格时保留最近的深度值
- **形态学膨胀 (Morphological_Dilation)**: 图像处理操作，用于扩展稀疏深度图的覆盖范围
- **SID (Spacing_Increasing_Discretization)**: 对数间距的深度分桶策略，近处密集远处稀疏

## 需求列表

### 需求1：稀疏深度GT生成

**用户故事：** 作为开发者，我希望能够从LiDAR点云生成用于深度监督的稀疏深度GT，以便训练深度估计网络。

#### 验收标准

1. 当处理LiDAR点云时，系统应当将点云投影到各相机图像平面，并下采样至LSS特征图尺度（通常stride=16）
2. 当下采样过程中遇到多个激光点落入同一网格时，系统应当执行**最小深度池化（Min Pooling）**，仅保留最近点的深度
3. 系统应当对生成的稀疏深度图执行**形态学膨胀（Morphological Dilation）**操作（如3x3核），以增加监督信号密度
4. 当生成深度GT时，系统应当将连续深度值根据配置（Uniform/SID）离散化为深度bin索引
5. 系统应当正确处理图像数据增强变换（Resize, Crop, Flip, Rotate），确保深度图与增强后的图像几何一致
6. 当生成深度GT时，系统应当过滤掉超出深度范围(dbound)的点
7. 当生成深度GT时，系统应当生成有效掩码(valid_mask)标记有深度值的像素位置

### 需求2：深度监督损失函数

**用户故事：** 作为开发者，我希望能够计算深度预测与GT之间的损失，以便显式优化深度估计网络。

#### 验收标准

1. 深度损失模块应当支持Binary Cross Entropy Loss计算深度分布损失
2. 深度损失模块应当支持Focal Loss以处理深度分布的类别不平衡问题
3. 深度损失模块应当只在有效像素位置（valid_mask=True）计算损失
4. 深度损失模块应当支持可配置的损失权重(depth_loss_weight)
5. 当稀疏深度图为空时，深度损失模块应当返回零损失

### 需求3：Camera-Aware深度网络

**用户故事：** 作为开发者，我希望深度估计网络能够感知不同相机的内参、外参和数据增强差异，以便针对不同相机自适应调整深度预测。

#### 验收标准

1. Camera-Aware模块应当将**相机内参(3x3)、相机外参(旋转+平移)以及图像数据增强矩阵(IDA)**联合编码为特征向量
2. Camera-Aware模块应当使用MLP对编码后的参数进行映射，并使用SE（Squeeze-and-Excitation）机制调制图像特征
3. Camera-Aware模块应当支持可配置的编码维度(embed_dim)
4. 当处理多视角图像时，Camera-Aware模块应当为每个相机独立编码参数
5. Camera-Aware模块应当与现有的深度网络(depthnet)无缝集成

### 需求4：增强的视角变换模块

**用户故事：** 作为开发者，我希望有一个集成了深度监督和Camera-Aware的视角变换模块，以便在训练时同时利用这两个特性。

#### 验收标准

1. 增强的视角变换模块应当继承自现有的DepthLSSTransform
2. 增强的视角变换模块应当在前向传播时返回深度预测用于计算损失
3. 增强的视角变换模块应当支持可选的Camera-Aware功能（通过配置启用/禁用）
4. 增强的视角变换模块应当支持可选的深度监督功能（通过配置启用/禁用）
5. 当禁用所有增强功能时，模块行为应当与原DepthLSSTransform一致

### 需求5：训练流程集成

**用户故事：** 作为开发者，我希望深度监督损失能够集成到BEVFusion的训练流程中，以便端到端训练。

#### 验收标准

1. BEVFusion模型应当在loss方法中包含深度监督损失
2. 深度监督损失应当与检测损失一起反向传播
3. 深度监督损失应当在TensorBoard中可视化（loss_depth）
4. 当未配置深度监督时，训练流程应当与原BEVFusion一致
5. 深度监督损失权重应当可通过配置文件调整

### 需求6：数据管道集成

**用户故事：** 作为开发者，我希望深度GT的生成能够在数据加载阶段完成，以便充分利用CPU多进程预处理，不阻塞GPU训练。

#### 验收标准

1. 深度GT生成应当封装为独立的Data Pipeline类（如LoadDepthFromPoints）
2. Data Pipeline应当在CPU数据加载阶段完成深度GT计算
3. Data Pipeline应当将深度GT存储在results字典中，供模型训练时使用
4. Data Pipeline应当支持配置深度分桶策略（Uniform或SID）
5. Data Pipeline应当支持配置形态学膨胀的核大小

### 需求7：配置与集成

**用户故事：** 作为开发者，我希望能够通过配置文件灵活配置深度监督和Camera-Aware特性，以便进行消融实验。

#### 验收标准

1. 配置应当支持独立启用/禁用深度监督功能
2. 配置应当支持独立启用/禁用Camera-Aware功能
3. 配置应当支持指定深度损失类型（BCE或Focal Loss）
4. 配置应当支持指定深度损失权重
5. 配置应当支持指定深度分桶策略（Uniform或SID）
6. 配置应当遵循与现有BEVFusion配置相同的模式

### 需求8：代码复用与简洁性

**用户故事：** 作为开发者，我希望新增功能能够复用现有模块，以便代码库保持可维护性。

#### 验收标准

1. Camera-Aware模块应当复用mmcv/mmdet中的SE模块或实现轻量级版本
2. 新增代码应当遵循与现有BEVFusion代码相同的编码风格
3. 新增代码应当为关键函数提供中文注释
4. 新增模块应当以最小的代码改动集成到现有文件中
5. 深度GT生成逻辑应当与现有的LiDAR投影逻辑保持一致性
