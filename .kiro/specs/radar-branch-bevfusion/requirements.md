# 需求文档

## 简介

本文档定义了在BEVFusion框架中重新设计毫米波雷达分支的需求。该设计基于**几何感知型多路径雷达融合架构**，核心理念是通过**特征工程**恢复雷达点云的物理几何属性，并通过**双路径解耦**的设计，同时发挥雷达在"语义识别"和"物理测速"两个维度上的优势。

设计目标是符合nuScenes数据集格式规范，保持代码的可读性和简洁性，并尽可能复用mmdetection3d中已有的模块。

## 术语表

- **BEV (Bird's Eye View)**: 鸟瞰图，一种从上方俯视的2D表示，用于统一不同传感器的特征
- **雷达分支 (Radar_Branch)**: 毫米波雷达处理分支，负责将雷达点云转换为BEV特征
- **雷达点云 (Radar_Points)**: 毫米波雷达点云数据，nuScenes中包含18维特征
- **语义特征路径 (Semantic_Path)**: 负责提取雷达的语义特征（RCS、空间分布等），用于辅助物体识别
- **物理速度路径 (Velocity_Path)**: 负责保留雷达的高精度多普勒速度测量值
- **方位角 (Azimuth_Angle)**: 目标相对于传感器的水平角度θ，用于理解径向速度的物理置信度
- **径向速度 (Radial_Velocity)**: 雷达测量的沿视线方向的速度分量
- **速度不确定度 (Velocity_RMS)**: 雷达测量速度的误差估计（vx_rms, vy_rms）
- **几何增强 (Geometry_Enhancement)**: 通过计算sin θ和cos θ引入方位角信息
- **融合层 (Fusion_Layer)**: 多模态融合层，负责融合图像、激光雷达和雷达的BEV特征
- **Pillar编码器**: 基于PointPillars的点云编码方式，将点云转换为伪图像表示
- **体素化 (Voxelization)**: 将点云离散化为规则的3D网格

## 需求列表

### 需求1：几何增强输入层

**用户故事：** 作为开发者，我希望能够对雷达点云进行几何增强预处理，以便模型能够理解径向速度的物理置信度。

#### 验收标准

1. 当加载雷达点云时，雷达数据加载器应当从原始18维特征中提取核心信息：x, y, z, rcs, vx_comp, vy_comp
2. 当预处理雷达点云时，系统应当实时计算方位角的三角函数值：sin θ = y/norm, cos θ = x/norm，其中norm = sqrt(x² + y²)
3. 当预处理雷达点云时，系统应当引入速度不确定度特征：vx_rms（索引16）和vy_rms（索引17）
4. 雷达预处理器应当输出10维增强点云特征向量：[x, y, z, rcs, vx_comp, vy_comp, sin_theta, cos_theta, vx_rms, vy_rms]
5. 如果点的norm值接近零，则系统应当将sin θ和cos θ设置为0以避免除零错误

### 需求2：语义特征路径（路径A）

**用户故事：** 作为开发者，我希望能够通过语义特征路径提取雷达的抽象BEV特征，以便辅助物体识别和定位。

#### 验收标准

1. 语义特征路径应当将增强后的雷达点云通过体素化转换为Pillar表示
2. 语义特征路径应当使用PillarFeatureNet对Pillar进行特征编码
3. 语义特征路径应当通过Scatter操作将Pillar特征散布到BEV空间
4. 语义特征路径应当输出64通道的BEV特征图，用于多模态融合
5. 当雷达点云为空时，语义特征路径应当返回形状正确的零填充BEV特征

### 需求3：物理速度路径（路径B）

**用户故事：** 作为开发者，我希望能够通过物理速度路径直接保留雷达的高精度速度测量值，以便检测头能够直接查询使用。

#### 验收标准

1. 物理速度路径应当使用轻量化MLP融合速度分量（vx, vy）与方位角特征（sin θ, cos θ）
2. 物理速度路径应当将融合后的速度信息直接投影到BEV网格
3. 物理速度路径应当输出4通道速度图：[vx, vy, rms, confidence]
4. 物理速度路径应当保留高精度的物理测量值，避免在深层卷积中被稀释
5. 当雷达点云为空时，物理速度路径应当返回形状正确的零填充速度图

### 需求4：三模态特征融合

**用户故事：** 作为开发者，我希望能够将雷达语义BEV特征与相机和LiDAR的BEV特征进行融合，以便利用所有传感器的互补信息。

#### 验收标准

1. 融合层应当接受来自相机（80通道）、LiDAR（256通道）和雷达语义特征（64通道）的BEV特征列表
2. 当融合特征时，融合层应当沿通道维度拼接所有BEV特征（共400通道）并应用卷积进行特征对齐和压缩
3. 融合层应当输出256通道的全局融合BEV特征图
4. 当任何模态被禁用时，融合层应当优雅地处理减少的输入数量
5. 雷达语义特征应当在融合中提供"冗余感知"能力，例如在烟雾或强光下通过RCS信息增强对物体的检测

### 需求5：检测头速度校准

**用户故事：** 作为开发者，我希望检测头能够利用物理速度路径的输出进行速度校准，以便输出高精度的速度估计。

#### 验收标准

1. 检测头应当根据预测的物体中心点，从物理速度图中采样对应的速度值
2. 检测头应当利用方位角特征（sin θ, cos θ）判断预测的运动方向是否符合雷达径向观测规律
3. 检测头应当结合网络预测值与雷达观测值，输出最终的高精度速度向量
4. 当物理速度图中某位置没有雷达观测时，检测头应当依赖网络预测的速度
5. 速度校准应当通过可学习的权重进行加权融合

### 需求6：数据加载与预处理

**用户故事：** 作为开发者，我希望能够从nuScenes数据集加载雷达点云数据并进行预处理，以便将雷达信息用于3D目标检测。

#### 验收标准

1. 当数据管道处理nuScenes样本时，雷达数据加载器应当从所有5个雷达传感器加载雷达点云
2. 当加载雷达点云时，雷达数据加载器应当使用标定矩阵将雷达点从传感器坐标系转换到LiDAR坐标系
3. 当加载雷达sweep时，雷达数据加载器应当支持加载多帧历史雷达数据并与当前帧拼接
4. 当预处理雷达点云时，雷达预处理器应当过滤掉超出指定点云范围的点
5. 当预处理雷达点云时，雷达预处理器应当应用与LiDAR点云相同的数据增强

### 需求7：模型配置与集成

**用户故事：** 作为开发者，我希望能够通过配置文件配置雷达分支，以便轻松启用/禁用和调整雷达分支。

#### 验收标准

1. BEVFusion模型应当支持可选的雷达分支配置（语义路径和速度路径）
2. 当配置了雷达分支时，BEVFusion模型应当提取雷达特征并将其包含在融合中
3. 当未配置雷达分支时，BEVFusion模型应当仅使用相机和/或LiDAR分支正常工作
4. 配置应当支持指定雷达特定参数（voxel_size, point_cloud_range, in_channels）
5. 配置应当遵循与现有LiDAR和相机分支配置相同的模式

### 需求8：代码复用与简洁性

**用户故事：** 作为开发者，我希望雷达分支的实现能够复用现有模块，以便代码库保持可维护性和一致性。

#### 验收标准

1. 雷达分支应当复用mmdetection3d中现有的Voxelization模块
2. 雷达分支应当复用mmdetection3d中现有的PillarFeatureNet或类似编码器
3. 雷达分支应当遵循与现有BEVFusion代码相同的编码风格和文档规范
4. 雷达分支应当以最小的代码改动实现对现有文件的修改
5. 雷达分支应当为关键函数提供中文注释以保持与现有代码的一致性
