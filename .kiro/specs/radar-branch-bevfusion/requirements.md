# 需求文档

## 简介

本文档定义了在BEVFusion框架中添加毫米波雷达分支的需求。该分支将与现有的图像分支和激光雷达分支并行工作，将雷达点云数据转换到统一的BEV（鸟瞰图）视图中进行多模态融合。设计目标是符合nuScenes数据集格式规范，保持代码的可读性和简洁性，并尽可能复用mmdetection3d中已有的模块。

## 术语表

- **BEV (Bird's Eye View)**: 鸟瞰图，一种从上方俯视的2D表示，用于统一不同传感器的特征
- **雷达分支 (Radar_Branch)**: 毫米波雷达处理分支，负责将雷达点云转换为BEV特征
- **雷达点云 (Radar_Points)**: 毫米波雷达点云数据，nuScenes中包含18维特征（x, y, z, dyn_prop, id, rcs, vx, vy, vx_comp, vy_comp, is_quality_valid, ambig_state, x_rms, y_rms, invalid_state, pdh0, vx_rms, vy_rms）
- **雷达编码器 (Radar_Encoder)**: 雷达特征编码器，将雷达点云编码为BEV特征
- **融合层 (Fusion_Layer)**: 多模态融合层，负责融合图像、激光雷达和雷达的BEV特征
- **nuScenes数据集**: nuScenes数据集，包含5个雷达传感器（RADAR_FRONT, RADAR_FRONT_LEFT, RADAR_FRONT_RIGHT, RADAR_BACK_LEFT, RADAR_BACK_RIGHT）
- **Pillar编码器**: 基于PointPillars的点云编码方式，将点云转换为伪图像表示
- **体素化 (Voxelization)**: 将点云离散化为规则的3D网格

## 需求列表

### 需求1：雷达数据加载

**用户故事：** 作为开发者，我希望能够从nuScenes数据集加载雷达点云数据，以便将雷达信息用于3D目标检测。

#### 验收标准

1. 当数据管道处理nuScenes样本时，雷达数据加载器应当从所有5个雷达传感器（RADAR_FRONT, RADAR_FRONT_LEFT, RADAR_FRONT_RIGHT, RADAR_BACK_LEFT, RADAR_BACK_RIGHT）加载雷达点云
2. 当加载雷达点云时，雷达数据加载器应当使用标定矩阵将雷达点从传感器坐标系转换到LiDAR坐标系
3. 当加载雷达点云时，雷达数据加载器应当支持可配置的特征维度（默认：x, y, z, rcs, vx_comp, vy_comp）
4. 当加载雷达sweep时，雷达数据加载器应当支持加载多帧历史雷达数据并与当前帧拼接
5. 如果雷达数据文件缺失或损坏，则雷达数据加载器应当优雅地处理错误并返回空的雷达点云

### 需求2：雷达点云预处理

**用户故事：** 作为开发者，我希望能够预处理雷达点云数据，以便将其正确编码为BEV特征。

#### 验收标准

1. 当预处理雷达点云时，雷达预处理器应当过滤掉超出指定点云范围的点
2. 当预处理雷达点云时，雷达预处理器应当应用与LiDAR点云相同的数据增强（旋转、缩放、平移、翻转）
3. 当预处理雷达点云时，雷达预处理器应当更新lidar_aug_matrix以保持几何一致性
4. 雷达预处理器应当支持可配置的雷达点云范围（可能与LiDAR范围不同）

### 需求3：雷达特征编码

**用户故事：** 作为开发者，我希望能够将雷达点云编码为BEV特征，以便与其他模态进行融合。

#### 验收标准

1. 雷达编码器应当将雷达点云转换为具有可配置输出通道数的BEV特征表示
2. 当编码雷达点云时，雷达编码器应当使用基于pillar的编码方式（类似PointPillars）以高效处理稀疏的雷达点云
3. 雷达编码器应当输出与LiDAR BEV特征具有相同空间分辨率的BEV特征，以确保融合兼容性
4. 当雷达点云为空时，雷达编码器应当返回形状正确的零填充BEV特征
5. 雷达编码器应当复用mmdetection3d中现有的体素化和pillar编码模块

### 需求4：三模态特征融合

**用户故事：** 作为开发者，我希望能够将雷达BEV特征与相机和LiDAR的BEV特征进行融合，以便利用所有传感器的互补信息。

#### 验收标准

1. 融合层应当接受来自相机、LiDAR和雷达分支的BEV特征列表
2. 当融合特征时，融合层应当沿通道维度拼接所有BEV特征并应用卷积
3. 融合层应当支持为每个模态配置输入通道数
4. 当任何模态被禁用时，融合层应当优雅地处理减少的输入数量
5. 融合层应当输出具有可配置输出通道数的融合BEV特征

### 需求5：模型配置与集成

**用户故事：** 作为开发者，我希望能够通过配置文件配置雷达分支，以便轻松启用/禁用和调整雷达分支。

#### 验收标准

1. BEVFusion模型应当支持可选的雷达分支配置（radar_voxel_encoder, radar_middle_encoder）
2. 当配置了雷达分支时，BEVFusion模型应当提取雷达特征并将其包含在融合中
3. 当未配置雷达分支时，BEVFusion模型应当仅使用相机和/或LiDAR分支正常工作
4. 配置应当支持指定雷达特定参数（voxel_size, point_cloud_range, in_channels）
5. 配置应当遵循与现有LiDAR和相机分支配置相同的模式

### 需求6：数据集支持

**用户故事：** 作为开发者，我希望雷达分支能够与nuScenes数据集格式兼容，以便在标准基准上进行训练和评估。

#### 验收标准

1. 数据集管道应当支持从nuScenes信息文件加载雷达数据
2. 当创建nuScenes信息文件时，数据转换器应当包含雷达传感器信息（路径、标定、sweep）
3. 数据集模态配置应当支持use_radar标志以启用/禁用雷达数据加载
4. 当use_radar为True时，数据集管道应当在数据字典中包含雷达点云

### 需求7：代码复用与简洁性

**用户故事：** 作为开发者，我希望雷达分支的实现能够复用现有模块，以便代码库保持可维护性和一致性。

#### 验收标准

1. 雷达分支应当复用mmdetection3d中现有的Voxelization模块
2. 雷达分支应当复用mmdetection3d中现有的PillarFeatureNet或类似编码器
3. 雷达分支应当遵循与现有BEVFusion代码相同的编码风格和文档规范
4. 雷达分支应当以最小的代码改动实现对现有文件的修改
5. 雷达分支应当为关键函数提供中文注释以保持与现有代码的一致性
